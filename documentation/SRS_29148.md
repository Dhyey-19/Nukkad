# Software Requirements Specification (SRS)
## Standard: ISO/IEC/IEEE 29148

### 1. Scope
This SRS defines requirements for the Nukkad Business Directory application. The system connects customers with local businesses, supports enquiries and subscriptions, and provides emergency directory access.

### 2. Normative References
- Supabase database schema: supabase_complete_schema.sql
- Project summary: PROJECT_COMPLETION_SUMMARY.md

### 3. Terms and Definitions
- Business owner: user role that manages business profiles and offers
- Customer: user role that searches and enquires
- Connect: a credit consumed when an enquiry is posted

### 4. Product/Service Perspective
- Mobile-first Flutter client
- Supabase backend and PostgreSQL data store
- Optional device services: geolocation, phone dialer, external links

### 5. Stakeholders and Users
- Customer users
- Business owners
- Admin users (assumed for moderation and configuration)

### 6. User Needs
UN-1 Customers need to find nearby or relevant businesses quickly.
UN-2 Customers need a simple way to contact businesses.
UN-3 Business owners need to manage profiles and offers.
UN-4 Business owners need insight into enquiries and analytics.
UN-5 Users need access to emergency numbers.

### 7. System Requirements
#### 7.1 Functional Requirements
SR-1 The system shall support onboarding and role selection.
SR-2 The system shall provide authentication (signup, login).
SR-3 The system shall allow business profile creation and updates.
SR-4 The system shall provide business discovery (search, filters, categories).
SR-5 The system shall allow customers to create enquiries.
SR-6 The system shall decrement connects for enquiry creation, except for unlimited plans.
SR-7 The system shall allow business owners to respond to enquiries.
SR-8 The system shall allow business owners to manage offers.
SR-9 The system shall support subscription records and status display.
SR-10 The system shall provide emergency numbers listing and call action.
SR-11 The system shall support reviews and ratings.
SR-12 The system shall support saved businesses.
SR-13 The system shall record analytics events for business interactions.
SR-14 The system shall provide notifications to users.

#### 7.2 Quality Requirements
- Performance: search and detail views should render within 3 seconds on typical mobile networks.
- Security: password hashing; RLS policies restrict access.
- Usability: onboarding and role selection must be simple and guided.
- Reliability: handle offline or poor connectivity with retries and clear error states.
- Maintainability: service layer separates backend logic.

### 8. Interface Requirements
#### 8.1 User Interfaces
- Customer dashboards: browse, search, and enquiry views
- Business dashboards: profile, enquiries, offers, subscription status
- Onboarding and authentication screens

#### 8.2 External Interfaces
- Supabase database and APIs
- Device services: location, phone dialer, external links

### 9. Verification
- Unit tests for service methods
- Integration tests for Supabase flows
- Manual test scripts for customer and business flows

### 10. Assumptions and Dependencies
- Supabase configuration is available and correct
- Payment gateway integration is TBD; transactions recorded by ID
- Admin UI is not defined in the current client
